## 1. 业务流程图 · 泳道视图

四个角色自上而下排列，横向箭头表示跨层协作。

> ⚠️ Mermaid 标准 `flowchart` **没有泳道（swimlane）语法**，此处用 `subgraph` 按角色分组近似实现：视觉上是「分成四块」，不是跨列对齐的真泳道。要严格泳道效果需用 `sequenceDiagram` 或专业绘图工具。

```mermaid
flowchart TB
    subgraph U["用户 · 创作者"]
        U1[打开工具<br/>进入工作台]
        U2[填写赛道·人群·语气]
        U3[选择创作入口]
        U4[挑选标题·编辑正文]
        U5[确认替换风险词]
        U6[复制成稿·保存草稿]
    end

    subgraph I["交互层 · 前端"]
        I0{是否已设置画像}
        I1[引导式表单<br/>四步一问·可跳过]
        I2[路由到对应模块<br/>带入账号画像]
        I3[选题卡片列表<br/>6–10 条可收藏]
        I4[创作页·步骤条<br/>标题→正文→标签]
        I5[高亮风险词<br/>等级与替换建议]
        I6[草稿箱·发布提醒]
    end

    subgraph E["生成引擎 · LLM"]
        E1[关键词选题生成<br/>对标笔记结构拆解]
        E2[标题·正文·标签<br/>按结构骨架生成]
        E3[执行合规扫描<br/>违禁·极限·敏感]
    end

    subgraph D["数据与合规层"]
        D1[热点与爆款语料<br/>对标笔记样本]
        D2[结构模板库<br/>干货·种草·教程]
        D3[违禁词·极限词<br/>词库版本化管理]
        D4[本地存储草稿<br/>支持导出 JSON]
    end

    U1 --> I0
    I0 -- 否 --> U2
    U2 --> I1
    I1 --> E1
    I0 -- 是 --> I2
    U3 --> I2
    I2 --> I3
    E1 --> I3
    I3 --> I4
    I4 <-->|双向| E2
    E2 <-->|双向| D2
    E2 --> E3
    E3 <-->|双向| D3
    E3 --> I5
    I5 <-->|双向| U5
    I5 --> I6
    U6 --> I6
    I6 --> D4
    E1 <-->|双向| D1

    classDef user fill:#FAEEDA,stroke:#BA7517,color:#633806
    classDef inter fill:#E1F5EE,stroke:#0F6E56,color:#085041
    classDef engine fill:#EAF3DE,stroke:#3B6D11,color:#27500A
    classDef data fill:#F1EFE8,stroke:#5F5E5A,color:#2C2C2A
    class U1,U2,U3,U4,U5,U6 user
    class I1,I2,I3,I4,I5,I6 inter
    class E1,E2,E3 engine
    class D1,D2,D3,D4 data
```

## 2. 业务流程图 · 主线视图

端到端主线，含 3 处判断分支与 4 处兜底。**这是信息密度最高、最适合讲解的一张。**

```mermaid
flowchart TD
    A[进入工具<br/>打开创作者工作台] --> B{是否已设置画像}
    B -- 否 --> C[引导设置账号画像<br/>四步一问·每步可跳过]
    C --> D[工作台首页<br/>三个创作入口]
    B -- 是 --> D
    D --> E{有无明确主题}
    E -- 没想法 --> F[关键词选题生成<br/>或对标笔记拆解]
    F --> G[产出选题卡片]
    E -- 有想法 --> G
    G --> H[标题生成<br/>5 选 1·标注风格与字数]
    H --> I[正文生成<br/>按笔记类型套结构骨架]
    I -. 缺具体数据时 .-> I2[缺数据留占位符<br/>不编造价格与功效]
    I --> J[标签生成<br/>大词·中词·小词分层]
    J --> K[合规检测<br/>违禁词·极限词·敏感词]
    K --> L{有风险词吗}
    L -- 是 --> M[一键替换·修改<br/>疑似风险标注人工确认]
    M --> K
    L -- 否 --> N[保存草稿·复制成稿<br/>草稿箱·发布提醒]

    classDef normal fill:#EAF3DE,stroke:#3B6D11,color:#27500A
    classDef decision fill:#FAC775,stroke:#854F0B,color:#412402
    classDef fallback fill:#FAECE7,stroke:#D85A30,color:#712B13
    classDef done fill:#EAF3DE,stroke:#3B6D11,stroke-width:2px,color:#27500A
    class A,C,D,F,G,H,I,J,K normal
    class B,E,L decision
    class I2,M fallback
    class N done
```

**四处兜底速查：**

| 位置 | 兜底 | PRD 依据 |
|---|---|---|
| 画像设置 | 全部跳过 → 用系统默认画像并提示完善 | 4.2.1 异常处理 |
| 选题生成 | 关键词过宽 → 提示补人群与场景；超时 → 自动重试 1 次 | 4.2.2 异常处理 |
| 正文生成 | 缺具体事实 → 留 `【请填入】`，禁止编造 | 4.2.4 事实性兜底原则（红线） |
| 合规检测 | 疑似隐晦导流 → 标注「疑似」提示人工确认 | 4.2.6 异常处理 |

## 3. 用户状态流转（补充视角）

> 这张图 **PRD 里没有**，是把 M1–M6 六个模块串成用户旅程，适合在作品集里讲「完整闭环」。

```mermaid
stateDiagram-v2
    [*] --> 未建档: 首次进入工具
    未建档 --> 已建档: 完成画像设置
    未建档 --> 默认画像: 全部跳过
    默认画像 --> 已建档: 后续补齐
    已建档 --> 选题中: 选择"找选题"
    已建档 --> 创作中: 选择"直接创作"
    选题中 --> 创作中: 选中选题"去写"
    创作中 --> 创作中: 换一批 / 重写段落
    创作中 --> 待检测: 生成完成
    待检测 --> 创作中: 命中风险词需修改
    待检测 --> 可发布: 全部处理完
    可发布 --> 已存草稿: 保存 / 复制
    已存草稿 --> [*]: 发布完成
```

## 4. PRD 原版页面流程图（留档对照）

> 摘自 PRD v1.0 第 6.1 节，**未作改动**。这是**页面视角**，与上面两张业务视角互为补充。

```mermaid
flowchart TD
    A[进入工具] --> B{是否已设置画像?}
    B -- 否 --> C[引导设置账号画像]
    B -- 是 --> D[首页/工作台]
    C --> D
    D --> E{选择入口}
    E -- 没想法 --> F[关键词选题生成]
    E -- 有想法 --> G[直接进入创作]
    E -- 有对标 --> H[对标笔记拆解]
    F --> I[选题卡片列表]
    I --> G
    H --> G
    G --> J[标题生成]
    J --> K[正文生成]
    K --> L[标签生成]
    L --> M[合规检测]
    M --> N{有风险词?}
    N -- 是 --> O[替换/修改]
    O --> M
    N -- 否 --> P[保存草稿 / 复制成稿]
    P --> Q[草稿箱]
    Q --> R[发布提醒]
```

**与主线视图的差异：**

| 差异点 | PRD 原版 | 主线视图 |
|---|---|---|
| 入口分流 | 三路（没想法 / 有想法 / 有对标） | 两路（没想法 / 有想法），拆解并入「没想法」 |
| 兜底分支 | 无 | 补入 4 处兜底（含事实留空红线） |
| 视角 | 页面跳转 | 业务步骤 |
| 深度 | 12 个节点 | 13 个节点 + 异常处理 |

## 附：两张补充说明

### Mermaid 渲染环境要求
- 飞书 / 腾讯文档 / Notion 均支持 `flowchart` 与 `stateDiagram-v2`
- GitHub / VS Code 需 Mermaid 插件
- **`classDef` 配色在部分平台会被忽略**（降级为默认灰蓝），属正常现象，不影响结构可读性
- `<br/>` 换行在飞书与腾讯文档中支持良好；若某平台不换行，去掉 `<br/>` 即可

### 待补的两个流程缺口（建议补进 PRD）
1. **断点续写缺状态入口** —— PRD 4.2.4 写了「生成中断保留已生成部分」，但流程图与原型都没有对应的恢复入口，建议在创作页补「恢复上次生成」的状态位。
2. **选题库断头** —— M2 的选题库（收藏 / 打分 / 备注）在第 4 步产出后就断了，没有回流到后续创作的闭环，建议补一条「选题库 → 直接创作」的通路。
