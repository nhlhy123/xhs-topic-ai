## 0. 结论先行（TL;DR）

**一句话定位建议**
> 不做"又一个小红书文案生成器"，做**「有数据依据的选题决策助手」**——用垂类爆款语料 + RAG，把"灵感"升级为"可验证的选题假设"。

**三条关键结论**

| # | 结论 | 依据 |
|---|---|---|
| 1 | **市场存在结构性空位**：通用大模型有 AI 无垂类数据，数据平台有数据无 AI 生成能力，垂类工具多数只是 Prompt 包装。"有数据 × 有生成"象限基本空白 | 第 3.2 章「三角不可能」分析 + 竞品定位图 |
| 2 | **Token 不是壁垒，获客才是**：单次生成边际成本仅 ¥0.008–0.06，Freemium 在算术上完全成立。真正的成本在 CAC、语料获取与合规 | 第 5.3 章 Unit Economics 测算 |
| 3 | **MVP 必须做减法**：砍掉一键发布、配图生成、多平台、数据大盘，只保留"输入账号定位 → 输出带数据依据的选题清单"这一条主线 | 第 6.1 章 不做清单 |

## 1. 市场背景与用户痛点

### 1.1 平台侧背景

小红书是**「搜索 + 推荐」双引擎**的内容平台，第三方数据工具实测普遍认为搜索流量占平台总流量的 **30%–50%**。这带来两个结构性后果：

- **选题权重被放大**：小红书的流量分发高度依赖"关键词命中 + 首屏点击率"，而这两件事 80% 在"选题阶段"就被决定了。选题错了，后面写得多好都是沉没成本。
- **数据成为刚需，但价格断层严重**：专业数据平台年费 1–5 万元，个人创作者完全无法承受；免费工具（小红书搜索框联想词、官方蒲公英）功能又太浅。**中间层的"轻量 + 有依据"需求无人承接。**

### 1.2 创作者的三大选题痛点

| 痛点 | 具体表现 | 本质是哪种问题 |
|---|---|---|
| **没网感** | 不知道什么话题"能爆"；写出来的标题一看就是"AI 味"，没有小红书语料特征 | 语料缺失 → 属于 **RAG 问题**，不是模型问题 |
| **找数据耗时** | 翻竞品首页、扒热搜榜、截图比对，单次选题花 40–60 分钟 | 检索效率问题 → 属于 **Agent 自动化问题** |
| **灵感枯竭** | 同一个账号做 3 个月后，选题高度同质化；不知道还能拍什么角度 | 多样性问题 → 属于 **采样策略 + 语料广度问题** |

> **产品判断**：这三个痛点对应三种技术解法，**不要用一个功能糊上去**。垂类工具最常见的失败就是把"没网感"当成"模型不够强"，结果换更贵的模型，问题依然存在——因为缺的是数据，不是算力。

### 1.3 核心用户画像（四类分层）

| 画像 | 粉丝/规模 | 核心诉求 | 付费意愿 | 决策速度 |
|---|---|---|---|---|
| **A. 新手博主** | 0–1 万粉 | "能发就行"、不想动脑 | 低（0–30 元/月） | 快，冲动型 |
| **B. 成长型博主 / 单人运营** | 1–10 万粉 | "能爆"、要差异化选题 | **中（30–100 元/月）** | 中，看重效果 |
| **C. 电商带货型** | 不限 | 选品 + 选题联动、转化导向 | 中高（100–300 元/月） | 中，ROI 算得清 |
| **D. 代运营 / MCN / 品牌方** | 多账号 | 批量产出、多账号调性隔离、结案报告 | **高（千元级/年）** | 慢，走流程 |

> **MVP 目标画像建议锁定 B 类**。理由：A 类付费意愿低于成本线，D 类需求复杂度会让 MVP 直接失焦。B 类是"痛点最痛 + 有能力付费 + 决策链条最短"的甜点区。

### 1.4 需求分层（关键概念区分）

```
灵感供给          选题决策              内容生产
（给想法）   →   （给判断依据）   →   （写正文/配图）
   ↓                  ↓                    ↓
  已极度内卷          ★ 空位 ★           红海
  （免费工具遍地）   （无人认真做）      （火兔/图小玉等）
```

**我们的战场在中间那一列。** 左边免费工具已经卷到不值钱，右边是视觉/模板类工具的主场，只有"选题决策"这一层，既需要数据又需要 AI，且竞品都做得不彻底。

## 3. 核心功能与 AI 能力对比（重点）

### 3.1 输入方式对比

| 竞品类别 | 输入方式 | 交互成本 | 致命缺陷 |
|---|---|---|---|
| 垂类 AI 工具 | 关键词输入框 + 下拉选择（类目/风格/平台） | 低 | **无信息增益**：你告诉它什么，它就还给你什么，不解决"不知道该写什么" |
| 通用大模型 | 自然语言对话（Prompt 自写） | **高**（需提示词能力） | 门槛高、无垂类数据锚定、结果不稳定 |
| 传统数据平台 | 关键词 + 多维筛选器（数据抓取式） | 中高 | 只给**数据表**，不给**内容**；看到爆款也不知道怎么抄 |
| **我方 MVP 目标** | **账号定位建档（赛道+人群+风格）+ 一键生成** | **最低** | —— |

> **关键洞察**：输入方式的设计本质是**"信息熵注入"**。下拉菜单是零信息增益的伪交互——真正有价值的输入是"账号定位"这类**结构性上下文**，它能被复用、能作为 RAG 的元数据过滤器。**MVP 应该用"一次建档、长期复用"替代"每次手打关键词"。**

### 3.2 AI 生成机制解剖：三角不可能

**核心论断**：当前市场上不存在"AI 能力强 × 垂类数据全 × 生成成本低"的三角全占者。

```
          AI 生成能力
               ▲
               │
   通用大模型   │   ★ 空位 ★
   豆包/Kimi    │   （有数据 × 有生成）
   有 AI 无数据  │   无成熟竞品
               │
 ──────────────┼──────────────► 垂类数据 / 语料
               │
   传统模板库    │   千瓜/新红/灰豚/新红
   无 AI 无数据  │   有数据 无生成能力
               │
```

**各竞品的实现层级拆解**

| 竞品类别 | 实现层级 | 技术真相 | 结论 |
|---|---|---|---|
| 通用大模型（豆包/DeepSeek） | **Prompt-only** | 纯靠 system prompt（角色设定 + 风格指令）+ 少量 few-shot。零检索、零实时数据 | 有泛化、无锚定。**必然产生幻觉与同质化** |
| 垂类 AI 工具（多数） | **Prompt-first（伪垂类）** | 把"小红书爆款标题公式"写进 Prompt 模板，本质是**提示词封装**，部分靠**后置校验**（违禁词词库）弥补 | 门槛极低，**随时可被通用模型迭代碾压** |
| 数据平台（千瓜/新红） | **Data-only** | 有真实爆款库、热搜词库、CES 评分体系，但**没有生成层** | 有数据无法消费，只能人肉解读 |
| **我方 MVP 目标** | **RAG + 结构化生成** | 向量检索爆款语料 → 重排 → 注入上下文 → 结构化输出 + 引用溯源 | 唯一能同时占住"数据"与"生成"的位置 |

#### 3.2.1 Prompt 工程的关键动作（我方 MVP 必须具备）

| 技术动作 | 作用 | 不做的后果 |
|---|---|---|
| **角色 + 平台语料锚定** | system prompt 明确"你是小红书 X 赛道运营"，注入平台特有句式与语气 | 输出"AI 味"浓，"姐妹们"满屏堆砌 |
| **Few-shot 爆款样例** | 3–5 条真实爆款标题作为示例（而非描述） | 模型只能"描述爆款"，不能"模仿爆款" |
| **CoT 拆解链** | 让模型先输出"这个选题的钩子类型/目标人群/情绪触发点"，再生成标题 | 结果不可解释、无法微调 |
| **负向 Prompt（禁用词表）** | 显式禁止"最、第一、绝对、100%、稳赚"等极限词与平台违规词 | 生成即违规，用户发布被限流 |
| **结构化输出约束** | JSON Schema / Function Calling 强制字段（标题/痛点/大纲/标签） | 输出格式漂移，前端无法渲染 |

#### 3.2.2 RAG 检索增强生成（差异化核心）

**语料库设计**

| 维度 | 设计要点 |
|---|---|
| 语料来源 | 近 90 天赛道内高互动笔记（点赞+收藏+评论/曝光）的结构化字段：标题、正文、标签、互动量、发布账号粉丝量级 |
| 切分策略 | **按"笔记"整篇切分，而非按段落**——小红书笔记结构短（300–800 字），整篇作为语义单元才能保住"选题-结构"的完整对应关系 |
| 元数据过滤 | 类目、粉丝量级（低粉爆文权重更高）、时间衰减（T-7 天权重 ×1.5，T-30 天 ×1.0，T-90 天 ×0.6） |
| 召回→重排 | 向量召回 Top-20 → 按"互动率 × 时间衰减 × 账号体量匹配度"重排 → 取 Top-8 注入 |
| 引用溯源 | 每个生成选题标注参考来源（"参考近 7 天 3 篇同量级爆款结构"），**既是信任资产，也是可审计的证据链** |

**RAG 带来的 Token 放大效应（重要工程判断）**

| 环节 | 无 RAG | 有 RAG |
|---|---|---|
| 输入 Token | ~1.2k | ~4.5k（+3.3k 检索上下文） |
| 输出 Token | ~1.8k | ~1.8k |
| 输入成本倍数 | 1× | **3.75×** |
| 但输入单价仅为输出单价的 1/3–1/5 | —— | **总成本抬升约 1.5–2×** |

> **结论**：RAG 的信息增益远大于成本代价。3 倍输入 Token 换来的是"有依据"这个核心卖点，**这个账划得来**。

**Prompt Caching 是毛利关键**
system prompt + few-shot 是固定前缀，可走前缀缓存（Prompt Caching）。参考国产模型公开策略，缓存命中后输入价格可降至原价的 10%–50%（例：Kimi 缓存命中输入约 ¥2/百万 Token vs 常规 ¥20/百万）。**高频调用场景下，开不开缓存直接决定毛利能不能过 80%。**

#### 3.2.3 实时热点数据（我方最大短板，必须有过渡方案）

| 方案 | 时效性 | 成本 | 合规风险 | MVP 建议 |
|---|---|---|---|---|
| 平台公开接口 / 官方数据 | 实时 | 低 | 低 | ✅ 优先（蒲公英等） |
| 第三方数据平台 API | 滞后 3–7 天 | 高 | 中 | ⚠️ 付费阶段再接 |
| 自建爬虫 | 准实时 | 中 | **高（法律风险）** | ❌ MVP 阶段不碰 |
| 人工运营热点词表（每周维护） | 滞后 ≤7 天 | 低 | 低 | ✅ **MVP 首选过渡方案** |

> **MVP 决策**：用"人工维护的赛道热点词表 + 平台公开热搜"替代实时数据，对外话术诚实标注数据时效（如"基于近 7 天"）。**宁可坦白时效，也不要假装实时——这是 AI 产品最容易被用户识破的信任点。**

#### 3.2.4 大模型幻觉（Hallucination）：具体风险与对策

| 幻觉类型 | 具体表现 | 对策 |
|---|---|---|
| **数据幻觉** | 编造"该话题搜索量 10 万+"、"这篇笔记点赞破 5 万" | 数据类表述**禁止模型自由生成**，改为从数据源注入占位符，模型只负责解释 |
| **事实幻觉** | 编造不存在的热门话题/活动/竞品名 | 输出后置校验：实体存在于语料库白名单才放行 |
| **合规幻觉** | 生成极限词、医疗功效宣称、诱导互动话术 | 违禁词库正则 + 语义双校验，命中即改写或拦截 |
| **格式幻觉** | 该给 10 个选题只给 7 个，字段缺失 | JSON Schema 强约束 + 字段校验兜底重试 |

### 3.3 输出内容结构化程度对比

| 竞品 | 标题 | 核心痛点 | 内容大纲 | 标签 | 数据依据 | 结构化程度 |
|---|---|---|---|---|---|---|
| 通用大模型（Prompt 模式） | ✅ | ⚠️ 需明确要求 | ⚠️ 需明确要求 | ⚠️ 时有时无 | ❌ | **中（不稳定）** |
| 易撰 / 文案狗 / 5118 | ✅（含评分） | ❌ | ❌ | ⚠️ 部分 | ⚠️ 关键词热度 | **低（仅标题层）** |
| Reditor / 万文 / 薯AI小蜜 | ✅ | ⚠️ 部分 | ✅ 正文 | ✅ | ❌ | **中高（重正文）** |
| 千瓜 / 新红 / 灰豚 | ⚠️ 爆款原文 | ❌ | ❌ | ⚠️ 话题标签 | ✅ **强** | **低（只有数据）** |
| **我方 MVP 目标** | ✅ | ✅ | ✅ | ✅ | ✅ **每个选题带依据** | **高（决策导向）** |

> **关键差异点**：竞品要么"只给标题"（工具类），要么"直接给正文"（写作类），**没有一个在"选题决策"这一层给出完整信息包**。我们定义的最小完整单元：

```
选题单元 = 标题 + 核心痛点 + 3 点大纲 + 推荐标签 + 数据依据（参考笔记量级/时效）
```

### 3.4 AI 交互体验对比

| 体验维度 | 竞品现状 | 我方设计标准 | 技术实现 |
|---|---|---|---|
| **流式输出（打字机）** | 通用大模型 ✅；多数垂类工具 ❌（转圈等待） | **必须做** | SSE 流式推送 |
| **首 Token 延迟（TTFT）** | 普遍 2–5s | **< 1.5s**（体感分水岭） | 轻量模型前置 + 缓存预热 |
| **全量生成时间** | 8–20s | 分段交付：标题列表先出（~3s），大纲按需展开 | 渐进式交付，用户可中断 |
| **"换一批"** | 多数是"重新抽一次"（同质化） | **真多样性** | 提高 temperature + Embedding 相似度阻尼去重（与上一批余弦相似度 > 0.9 则丢弃重采样） |
| **微调追问** | 弱，多为重新输入 | 支持"再具体点/换个角度/更接地气" | 会话状态维护 + 意图路由（选题/扩写/仿写/标题优化 分属不同 Prompt 模板） |
| **多轮对话** | 通用大模型 ✅，垂类工具 ❌ | 3 轮内解决问题 | 上下文窗口管理 + 历史压缩 |
| **失败兜底** | 超时即报错 | 降级 + 重试 + 友好话术 | 模型超时 8s 切备用；幻觉拦截后自动重生成一次 |

**"换一批"的坑（很多产品死在这里）**
> 大多数产品的"换一批"只是再调一次 API，结果 70% 内容重复——因为模型在高 temperature 下依然倾向于高频模式。**正确做法是"多样性阻尼"：把上一批结果向量化，新结果与之相似度超阈值即丢弃重采样。** 这是"看起来像做了"和"真的做了"的分界线。

**生成速度基准（自测目标）**

| 阶段 | 目标 | 说明 |
|---|---|---|
| 首 Token | < 1.5s | 低于此值用户感知为"即时" |
| 标题列表（10 条） | < 4s | 满足"先给结果"的心理预期 |
| 完整信息包 | < 12s | 流式可读，不产生等待焦虑 |

## 4. AI 产品 SWOT 分析（针对我方 MVP）

### S — 优势（Strengths）

| 优势 | 来源 | 可持续性 |
|---|---|---|
| **垂类语料更懂小红书** | 自建赛道爆款语料库 + RAG 锚定 | 高（语料是时间的朋友，越攒越厚） |
| **"有依据"的差异化定位** | 每个选题附数据来源，从"灵感"升级为"决策" | 高（定位差异，不靠模型能力） |
| **轻量、决策链短** | 无历史包袱，可用最新模型与最简架构 | 中 |
| **成本结构极优** | 单次边际成本 < ¥0.06，Freemium 无压力 | 高 |

### W — 劣势（Weaknesses）

| 劣势 | 影响 | 缓解方案 |
|---|---|---|
| **缺乏实时热点数据** | 选题时效性弱于数据平台 | 人工维护热点词表 + 诚实标注时效；付费阶段再接第三方 API |
| **语料冷启动** | 初期无爆款库，RAG 召回质量差 | 先用公开榜单/人工采编 2000–5000 条种子语料 |
| **用户信任成本高** | 新工具无背书，"AI 生成"易被质疑 | 用"溯源引用"替代"品牌背书"——逻辑赢过资历 |
| **合规边界模糊** | 数据获取方式有法律风险 | 不碰爬虫，走官方/合规采购路径 |

### O — 机会（Opportunities）

| 机会 | 判断依据 |
|---|---|
| **垂直场景付费意愿被验证** | 万文 ¥48/月、薯AI小蜜 ¥498/年、易撰 ¥199 终身 —— 低价档位已被市场教育 |
| **中间层市场无人占位** | 数据平台太贵（¥1599+/月起），免费工具太浅，¥19–49/月档位供给质量差 |
| **矩阵号批量运营需求真实** | 软文高频推同类工具，说明有真实搜索与购买需求 |
| **通用模型能力提升 = 我方成本下降** | 模型越强越便宜，我们的 Prompt/RAG 层直接受益（**威胁的反面就是机会**） |

### T — 威胁（Threats）

| 威胁 | 严重度 | 应对策略 |
|---|---|---|
| **通用大模型能力迭代直接碾压** | 🔴 高 | 不与其比"生成质量"，比"数据锚定 + 决策闭环"。模型越强，我们的语料价值越大 |
| **平台官方下场** | 🟡 中 | 官方做工具必做标准化，不做垂类深度。我们保持细分赛道纵深 |
| **豆包等内置小红书模板** | 🔴 高 | 通用助手是"人人可用的通用件"，我们是"赛道专属件"，靠语料厚度建护城河 |
| **数据版权与合规收紧** | 🟡 中 | 尽早建立合规语料获取路径（官方合作 > 采购 > 人工采编） |
| **同质化工具低价内卷** | 🟡 中 | 不做纯 Prompt 包装，用 RAG 建立不可复制的数据资产 |

> **【批判性分析】最危险的自我欺骗**
> 如果用"更贵的模型 + 更长的 Prompt"来做这个产品，它在 GPT 下一次迭代时就会被清零。**唯一不会被碾压的资产是"你独有的、持续更新的垂类语料库"以及"用户账号定位建档数据"。** 这两样东西与模型能力无关，只与时间和运营有关。MVP 的资源分配应该向语料建设倾斜，而不是向模型调优倾斜。

| **联盟/软文矩阵** | 火兔、okbob 等 | "实测 5 款神器"式软文铺量 | 🟡 中（有效但伤品牌） |

### 5.2 变现模式拆解

| 模式 | 代表竞品 | 价格锚点 | 适用我方阶段 |
|---|---|---|---|
| **Freemium + 积分/次数包** | 万文（1000 点 ¥48） | 免费额度 + 加购 | ✅ **MVP 首选** |
| **订阅制** | 万文 ¥48/月、薯AI小蜜 ¥50/月 | ¥19–49/月 | ✅ 主变现方式 |
| **按次付费** | 易撰 ¥29/月、¥199 终身 | ¥0.1–1/次 | ⚠️ 可作补充 |
| **卖课 / 私域训练营** | 各类博主 | ¥199–999 | ⚠️ 后续（利润高但重运营） |

| **高客单数据订阅** | 千瓜 ¥1599+/月 | 万元/年 | ❌ 不适用 MVP |

> **竞品的钱在哪**：数据平台卖"数据（高客单、低频、长决策）"，AI 工具卖"效率（低客单、高频、短决策）"。**我们选后者，但用前者做信任背书。**

### 5.3 单位经济模型（Unit Economics，MVP 关键测算）

**单次生成成本估算**（生成 10 个完整选题信息包）

| 项目 | Token 量 | 轻量模型单价 | 成本 |
|---|---|---|---|
| 输入：system prompt + few-shot | ~1.2k | ¥0.6–1.0/百万 | ¥0.0010 |
| 输入：RAG 检索上下文（Top-8） | ~3.3k | ¥0.6–1.0/百万 | ¥0.0026 |
| 输入：用户输入 + 会话历史 | ~0.4k | ¥0.6–1.0/百万 | ¥0.0003 |
| 输出：10 个选题信息包 | ~1.8k | ¥2–3/百万 | ¥0.0044 |
| **合计（轻量模型）** | | | **¥0.008** |
| **合计（旗舰模型）** | 同上 | 输入 ¥3–8 / 输出 ¥15–30/百万 | **¥0.058** |

**毛利模型（按轻量模型 + Prompt Caching）**

| 指标 | 数值 |
|---|---|
| 单次生成实付成本（含缓存） | ¥0.004–0.008 |
| 免费用户成本（5 次/天） | ¥0.02–0.04/天 → **约 ¥0.9/月** |
| 付费定价（订阅制） | ¥39/月（对标 ¥48/月 竞品锚点） |
| 假设重度用户 300 次/月 | 成本 ¥1.2–2.4 → **毛利 > 93%** |
| 免费→付费转化 3% 时的分摊成本 | 33 个免费用户 × ¥0.9 = ¥29.7 → **需 ARPU > ¥30 才打平** |

> **【决策锁校验】关键数字红线**
> - 单次生成成本必须 **< ¥0.05**（超过说明 RAG 上下文失控或模型选型错误）
> - 免费额度上限 **5 次/天**（若无上限，滥用会导致成本击穿）
> - 转化率红线 **≥ 3%**（低于此值 Freemium 不成立，必须转向按次付费）
> - 付费定价 **≥ ¥39/月**（低于此值无法覆盖分摊的免费用户成本）

## 6. 对我方 MVP 的启示与差异化打法

### 6.1 必须砍掉的功能（不做清单）

| 砍掉的功能 | 砍掉理由 |
|---|---|
| ❌ **一键发布 / 账号托管** | 小红书无开放接口，自动化发布属平台违规，法律与封号风险极高 |
| ❌ **配图 / 封面生成** | 视觉赛道是图小玉/Canva 的主场，非我们能力半径 |
| ❌ **违禁词检测（独立模块）** | 降级为生成环节的**隐式后置校验**，不做成独立功能，避免增加认知负担 |
| ❌ **多平台支持（抖音/公众号）** | 一上来就做多平台 = 每个平台都做不深，垂直纵深才是护城河 |
| ❌ **数据大盘 / 达人库 / 投放分析** | 这是千瓜新红的战场，年费万元级，进不去也不要进 |
| ❌ **手机 App** | 先用网页/小程序验证需求，App 是留存工具不是验证工具 |
| ❌ **团队协作 / 多账号管理** | 属 D 类客户需求，会直接让 MVP 失焦 |
| ❌ **免费无限次** | 成本失控风险，且会摧毁付费转化意愿 |
| ❌ **自建爬虫获取数据** | 合规红线，MVP 阶段绝不触碰 |

### 6.2 MVP 保留的唯一主线

```
一次建档（赛道 + 人群 + 风格）
        ↓
一键生成 10 个选题
        ↓
每个选题 = 标题 + 核心痛点 + 3 点大纲 + 推荐标签 + 数据依据
        ↓
换一批（真多样性） / 拆解仿写 / 展开成正文骨架
```

**就这四步。** 任何不服务于这条主线的功能，MVP 阶段都不做。

### 6.3 差异化切入点（2 个，建议二选一或先做 A 再做 B）

#### 切入点 A：单赛道纵深 —— 「有依据的选题」

**做法**：不做全类目。选定 **1 个赛道**（建议家居 / 母婴 / 职场干货，这类内容结构性强、语料可采集性好），自建 2000–5000 条近 90 天爆款笔记语料库 + 赛道热点词表，用 RAG 生成"带数据依据的选题"。

**为什么通用大模型做不到**：它没有这 5000 条语料，也不知道这个赛道最近 7 天什么结构在爆。

**为什么数据平台做不了**：它没有生成层，用户看完数据还是要自己想。

**壁垒**：语料库是**时间的朋友**——每多运营一个月，护城河深一分，且与模型迭代无关。

#### 切入点 B：「爆款拆解 → 跨账号仿写」Agent

**做法**：用户输入一个爆款笔记链接/截图 → Agent 自动完成：
1. **OCR + 结构化拆解**：钩子类型（悬念/数字/反常识/身份认同）、痛点层次、内容结构模板、情绪曲线、标签组合逻辑
2. **抽象为可复用模板**：输出"这个爆款的结构骨架"，而非原文改写
3. **跨账号仿写**：结合用户自己的账号定位（赛道+人群+风格），生成贴合自身调性的仿写选题

**为什么这是黄金交叉位**：
- 通用大模型做不好 —— 缺赛道语料锚定，拆解停留在表面（"标题用了数字"这种没用的结论）
- 数据平台做不了 —— 有爆款库但无生成能力
- 现有 AI 工具做不到 —— 只做"改写"（一键洗稿），不做"结构迁移"

> **【批判性分析】切入点 B 的真实风险**
> "爆款拆解"很容易滑向"洗稿工具"，而洗稿是平台明确打击的行为，且会让产品陷入法律与道德的双重灰区。**必须把产品定义严格锚定在"结构模板 + 品类迁移"（抽离结构、换赛道重做），而非"同质改写"。** 这个边界如果第一天不划清，产品会自己长歪。

### 6.4 最小可行技术架构

```
用户输入（账号定位建档）
    ↓
意图路由（生成选题 / 换一批 / 拆解仿写 / 展开正文）
    ↓
RAG 检索层
  向量库（爆款语料 Embedding）
  + 元数据过滤（赛道 / 粉丝量级 / 时间衰减）
  + 重排（互动率 × 时效 × 体量匹配）
    ↓
Prompt 组装层
  system（角色+禁用词） + few-shot（真实爆款样例）+ RAG 上下文 + JSON Schema
    ↓
LLM 生成（轻量模型主力 + 旗舰模型兜底）
    ↓
后置校验层
  违禁词扫描 → 实体白名单校验 → 字段完整性校验 → 失败重试
    ↓
SSE 流式输出（渐进式交付）
    ↓
引用溯源展示（每个选题标注数据依据）
```

### 6.5 验证指标与上线门槛

| 指标类型 | 指标 | 上线门槛 |
|---|---|---|
| **北极星指标** | **选题采用率**（生成选题中被用户收藏/实际发布的比例） | ≥ 30% |
| 体验 | 首 Token 延迟（TTFT） | < 1.5s |
| 体验 | 完整信息包生成时间 | < 12s |
| 体验 | "换一批"结果去重率（与上一批相似度 < 0.9 的占比） | ≥ 80% |
| 成本 | 单次生成成本 | < ¥0.05 |
| 成本 | 免费用户月均成本 | < ¥1.5 |
| 增长 | 7 日留存 | ≥ 25% |
| 商业 | 免费→付费转化率 | ≥ 3% |
| 质量 | 输出违规率（违禁词命中未拦截） | = 0 |

## 7. 风险与合规清单

| 风险 | 等级 | 应对 |
|---|---|---|
| **数据获取合规** | 🔴 高 | MVP 阶段只用公开渠道 + 人工采编，不使用爬虫抓取用户数据 |
| **内容合规（违禁词/极限词）** | 🔴 高 | 生成侧负向 Prompt + 输出侧词库双校验，违规率必须为 0 |
| **AI 生成内容责任** | 🟡 中 | 明确用户协议：AI 输出为参考建议，发布前需用户自行确认 |
| **模型幻觉导致误导** | 🟡 中 | 数据类表述一律由数据源注入，禁止模型自由发挥 |
| **版权风险（语料引用）** | 🟡 中 | 语料仅用于"结构学习"，不输出原文；提供溯源引用而非内容复制 |
| **平台政策变化** | 🟢 低 | 不做自动化发布，不依赖单一接口，保持轻耦合 |
