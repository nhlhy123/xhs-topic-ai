## 1. 市场与用户痛点

### 1.1 提问语言与知识库语言是两套系统

一线工人的报修表述，与厂家手册术语之间存在系统性错位。厂区里的实际说法：

| 手册标准术语 | 现场口语说法 |
|---|---|
| 伺服驱动器 | 伺服器 |
| 主轴温升异常 | 主轴烫手 |
| VMC-1160L | 1160 立加 |
| 主轴报警 SP-9012 | 报了个 90 几的码 |

具体后果有两条：关键词匹配在这种表达上直接失效；语义匹配会把"伺服器"召回成"服务器"。知识库越大，误召回的绝对量越高。

厂商在方言上的投入可以量化。[三] 一份 2026 年电话机器人测评显示，网易七鱼方言支持 8 种、智齿 11 种。同时智齿、腾讯云宣传的"70+ 语种"是出海多语种能力，服务海外客户，不解决车间方言。**这两件事常被混为一谈，是竞品宣传里最容易误读的一处。**

### 1.2 答错的代价不是差评，是停机和安全

消费品客服答错的成本是差评与退款。制造业不同：

- 设备停机按分钟计损，一条产线停一小时的经济损失通常高于一名一线客服一个月的薪资。
- 涉及高压、高温、机械传动的故障，错误指导可能造成人身伤害。
- 夜班通常只有 1–2 名值班工程师，AI 卡壳时没有第二层缓冲。

推论：**制造业售后 AI 的第一目标不是"降低人工成本"，而是"降低误答率与响应延迟"。** 成本节约是结果，不是卖点。

### 1.3 客户要的不是"答得多"，是"知道自己不该答"

通用客服产品的核心指标是独立解决率，越高越好。制造业不适用。设备报出安全类故障码时，AI 猜错一次就是事故。这个场景需要的是反向指标：**无答案认输率**。

|---|---|---|---|---|---|

| **智齿科技** | 传统 SaaS 客服 · AI 升级 | 客户联络一体化，软件 + BPO | 零售、金融、政企，覆盖 10+ 行业 | 坐席年费（标准版约 3580 元/坐席/年 [三]）+ 机器人版本 12980 / 19980 元 [三] + BPO 外包 | SaaS / 专属云 / 本地化 [官] |

| **售后宝 / 瑞云服务云**（补充） | 制造业垂直售后平台 | 全链路售后：报修 → 派工 → 备件 → 质检 | 装备制造、家电、新能源、医疗器械 | SaaS 订阅（按模块/用户）+ 实施服务，多需商务报价 | SaaS + PaaS，头部客户支持私有化 |

两点观察：

**单次对话的官方计价锚点。** 腾讯云消息条数包 5 万条 2800 元、100 万条 40000 元 [官]，折算约 **0.04–0.056 元/条** [官·推算]。自建按 Token 计费的单价区间很宽，闭源旗舰与开源模型可差一到两个数量级，单次会话成本取决于模型选择与上下文长度，不做直接对比。

**付费结构决定默认策略。** 前四类的收入以坐席数或订阅量为主，客户 KPI 是"减少人工"。垂直平台按模块和用户收费，客户 KPI 是"服务时效与一次解决率"。**收入结构的差异，会传导成转人工默认值的方向差异。** 这一点在第 3.3 节展开。

## 3. AI 核心能力深度对比

### 3.1 知识库（RAG）

| 维度 | 网易七鱼 | 智齿科技 | 腾讯云 | Dify / Coze 自建 | 售后宝 / 瑞云（垂直） |
|---|---|---|---|---|---|
| 切分策略 | 文档直导 + 自动语义切片；有知识萃取引擎，从历史对话自动提炼近义词与行业术语 [官] | 文档直导 + 自动语义切片；规则引擎与轻量 NLU 分流高频请求 [官] | 向量检索 + 全文检索混合，宣称日均处理百万级文档 [官] | 通用分段 / 父子分段等模式，参数由使用者自行调优 [三] | 结构化存储：图纸、故障方案、调试手册、BOM、维修视频、电路图 [官] |
| 多模态 | 支持图片、表格 [三] | 官网述多模态解析，对图纸/视频的支持程度未公开 [官·表述模糊] | 本地文档支持 docx / xlsx / csv / txt / md / pptx，单文件 ≤ 100MB、50 万字符 [官] | 依赖所用模型能力，需自行搭建解析链路 | 支持工程图纸、维修视频、BOM 照片，智能 BOM 可解析爆炸图 [官] |
| 召回准确率 | 未公开 | 问答准确率 95%+、独立解决率 80%+ [官·自报] | ADP 宣称准确率 ≥ 95% [官·自报] | 无 | 智能客服宣称分流 80% 标准化咨询 [官·自报] |
| 知识运营 | 知识萃取引擎自动提炼历史对话 [官] | 自然语言方式添加知识库 [官] | 知识库冷启动实施服务，需联系架构师报价 [官] | 需自建 | 工单可一键转知识库 [官] |

**关键判断：通用平台的"多模态"是"能传图片与表格"，不是"能理解工程图纸"。** 制造业真正需要的是从爆炸图、电路图、维修视频里检索，这块目前只有垂直平台在做。厂商自报的 95% 准确率没有公开评测集，相互之间不可横向比较，本报告不将其作为结论依据。

### 3.2 意图识别与槽位提取

核心问题是：能否多轮追问并提取【设备型号】和【故障代码】。

| 能力 | 网易七鱼 | 智齿科技 | 腾讯云 | Dify / Coze 自建 |
|---|---|---|---|---|
| 意图识别 | 多层级意图分类、行业术语/昵称映射、复合意图拆解 [官] | 规则引擎 + 传统 NLU + 大模型混合，快慢双系统分流 [三] | 大模型语义理解，支持复杂意图与多轮对话 [官] | 由使用者自行设计 |
| 多轮任务容量 | 按对话阶段（售前/售中/售后）配置策略 [官] | 多轮会话、一问多答、多机器人协作 [官] | 标准版 **5 个多轮任务**，专业版不限 [官] | 无硬性上限，受工程能力约束 |
| 型号 / 故障码槽位 | 有能力实现，但需按业务场景逐个配置对话流节点 | 同上 | 同上，且受多轮任务数量上限约束 | 需自己写 Prompt 与变量提取 |
| 行业术语库 | 知识萃取引擎 + 行业知识包 [官] | 依赖项目交付 | 依赖客户自建 | 无 |

**关键判断：槽位提取不是技术难点，是配置成本问题。** 通用平台都能做到型号追问，但需要运营逐个场景搭建。制造业的型号体系是系列 × 规格 × 年份的组合，逐场景配置的边际成本不可接受。腾讯云标准版"5 个多轮任务"的上限 [官] 就是一个可直接引用的量化证据——光设备系列就远不止 5 个。

### 3.3 异常兜底与转人工触发机制

| 触发维度 | 网易七鱼 | 智齿科技 | 腾讯云 | Dify / Coze 自建 | 行业参考值 |
|---|---|---|---|---|---|
| 关键词 / 白名单 | 支持用户主动要求、连续未识别、敏感词 [三] | 支持 | 支持意图触发 | 需自行实现 | 高优先级白名单，命中即 0 延迟直连人工 [三] |
| 置信度阈值 | 未公开默认值 | 未公开默认值 | 未公开默认值 | 需自行实现 | 通用建议 0.7 [三]；三层门控参考：ASR > 0.85 正常、0.65–0.85 待确认、0.45–0.65 追问两次不达标转人工；意图 top-1 > 0.9 且 margin > 0.2；知识最高相似度 < 0.65 则追问或转人工 [三] |
| 情绪识别 | 支持 [三·单一来源] | 不支持（其 AI Insight 做质检侧情绪）[三·单一来源] | 未公开 | 需自行实现 | 语速 / 音量 / 语调变化触发安抚式转接 [三] |
| 轮次兜底 | 支持 | 支持 | 支持 | 需自行实现 | 同一会话连续 3 轮意图无实质变化则强制中断 [三] |

**关键判断：转人工在通用平台上是一个"可配置项"，默认值偏向减少转人工**——因为客户的 KPI 是降本。制造业需要相反的默认值：安全类硬转、型号不明不猜。**默认值的方向差异，比功能清单的差异更本质。** 而 GB/T 47746—2026 的实施，把兜底机制从"体验优化项"抬成了"合规项"，这对一个以兜底为主线的产品是结构性利好。

## 5. SWOT 分析

### 优势 S

- **槽位设计垂直。** 型号与故障码是结构化枚举实体，通用平台按普通文本处理，语义相似度天然不可靠。
- **兜底是产品主线，不是配置项。** 默认值偏保守：宁可转人工，不可猜。
- **无历史包袱。** 可按大模型原生架构设计，不必兼容旧 NLU 栈与规则库。
- **自带评测集。** 可给出分层准确率，而不是一个无法验证的 95%。
- **合规红利。** GB/T 47746—2026 把转人工触发条件纳入标准要求。

### 劣势 W

- **无真实数据。** 无历史工单、无会话日志、无故障码库授权，冷启动靠公开说明书。
- **无工程沉淀。** 无 ASR、无高并发验证、无坐席工作台、无工单系统。
- **无交付能力。** 制造业客户普遍要求私有化、等保、信创适配，单人无法承接。
- **无信任资产。** 无案例、无资质、无行业背书，进不了大客户的供应商名录。

### 机会 O

- 兜底机制从"降本工具"升级为"合规组件"，需求从可选变必选。
- 制造业知识资产数字化程度低，师徒口述与纸质手册尚未结构化，知识工程是真实付费点。
- 通用平台在方言与术语映射上投入不足（方言支持 8–11 种），存在可切入的缝隙。
- 模型 API 成本持续下降，MVP 可在低预算下跑通闭环并给出实测指标。
- 存量制造业客服系统正处在 AI 换代窗口期。

### 威胁 T

- **价格锚点被平台压低。** 腾讯云 ADP 免费版给 15000 PU / 月 [三]，企业"先试平台"的决策门槛极低。
- **垂直平台的绑定效应。** 售后宝、瑞云把 AI 知识库嵌进工单、派工、备件链路，单点问答产品容易沦为配件。
- **绕过采购。** 客户 IT 部门可自行用 Dify 搭建，不需要外部供应商。
- **数据飞轮差距。** 垂直平台有"工单一键转知识库"，形成自增长的知识资产，MVP 无法复制。
- **大厂下沉垂直行业。** 华为云盘古 Agent 已明确以工业制造为落地方向 [三]。

## 6. 差异化定位与 MVP 启示

### 6.1 明确放弃的功能

| 放弃项 | 理由 |
|---|---|
| 全渠道接入（微信 / APP / 网页 / 电话） | 与竞品同质化，工程量大，不产生差异化证据 |
| 语音 / ASR | 涉及拾音、降噪、方言识别，是独立技术栈，MVP 做不好 |
| 坐席工作台 / 工单 / 派工 / 备件 | 售后宝与瑞云的护城河，正面进入无胜算 |
| 通用闲聊与多语言出海 | 与"安全兜底"的产品主张直接冲突 |
| 可视化 Agent 编排平台 | 平台公司的战场，做不过腾讯云和 Dify |
| 私有化部署与信创适配 | 单人无交付能力，只会出现在 POC 讨论中消耗精力 |
| 追求更高的独立解决率 | 与制造业的目标函数相反 |

### 6.2 单点突破口

一句话：**把"设备型号 + 故障代码"的定位准确率做到可验证，并明确划出"AI 不该回答"的边界。**

输入是一段口语报修（可能缺型号、可能只报错码、可能夹方言词），输出是结构化结果：

```json
{
  "设备型号": { "值": "VMC-1160L", "置信度": 0.92, "来源": "三轮追问 + 术语映射" },
  "故障代码": { "值": "SP-9012", "置信度": 0.88, "来源": "故障码库精确匹配" },
  "可能原因": ["...", "..."],
  "处置步骤": ["...", "..."],
  "风险等级": "high",
  "动作": "transfer_human"
}
```

三条设计原则，是 MVP 最该被记住的部分：

1. **槽位缺失必须追问，不允许模型补全。** 型号没问到就不答。这是与通用平台最本质的行为差异。
2. **故障代码走精确检索，不走语义模糊。** 代码是枚举值，模糊匹配本身就是错误来源。
3. **风险等级优先于置信度。** 高置信度不能覆盖高风险。安全类故障码命中即转人工，与置信度无关。

### 6.3 MVP 功能边界

**做：**
- 单轮 / 多轮对话 + 槽位追问（设备型号、故障代码）
- 术语映射表（口语词 → 标准术语 / 型号）
- 故障码库精确检索 + 处置方案 RAG
- 三层置信度门控 + 风险等级门控
- 转人工时输出结构化交接单（已提取槽位 + 已尝试方案 + 疑似原因）
- 评测集与分层指标看板

**不做：** 语音、全渠道、工单、派工、备件、编排平台、私有化。

### 6.4 验收指标

| 指标 | 定义 | 目标值（假设，需实测校准） |
|---|---|---|
| 槽位提取准确率 | 型号 / 故障码字段级 F1 | ≥ 0.90 |
| 故障码 Top-3 召回率 | 正确代码出现在前三位 | ≥ 0.95 |
| 无答案认输率 | 低置信时主动声明不确定的比例 | ≥ 0.90 |
| 危险误答率 | 高风险场景给出错误处置的比例 | ≈ 0（硬约束） |
| 转人工决策一致率 | 与人工标注结论的一致度 | ≥ 0.85 |
| 平均追问轮次 | 首轮到产出结构化结果 | ≤ 3 轮 |

### 6.5 要证明的那一件事

答辩时应该给出一句可以被反驳的话，而不是一句正确的空话：

> 在设备型号口语化表述的场景下，把故障码定位的 Top-3 召回做到 0.95，同时让 90% 的低置信场景主动认输。主流通用客服平台不会为这个场景收敛默认策略，因为它们的产品 KPI 是降低转人工率。

## 7. 待验证清单

1. **GB/T 47746—2026 的具体条款。** 目前依据的是厂商解读，需查标准原文确认转人工触发条件是否为强制要求。这是第 5 节"合规红利"判断的前提。
2. **各厂商当前报价。** 腾讯云的机器人价格与消息条数包来自官方计费文档 [官]；七鱼与智齿的坐席价格来自第三方问答站与测评 [三]，可能已过时，需以商务报价为准。
3. **厂商自报指标的适用性。** "独立解决率 80%+""问答准确率 95%+"均为厂商自报，无公开评测集，不可横向比较，本报告未将其作为结论依据。
4. **制造业客户的真实付费意愿。** 需向 3–5 家制造业售后负责人验证：他们为"减少误答"付费，还是只为"减少人工"付费。这决定定价逻辑与产品叙事。
5. **一份技术对比数据的可用性。** "规则引擎 55% / 传统 NLP 72% / BERT+Faiss 91%"出自单一技术博客，不构成行业结论，本报告未引用其具体数值。
